# Интерпретатор AST

Программа принимает путь к JSON-файлу с AST и выполняет его. Значениями языка могут быть 32-битные целые числа, строки и изменяемые массивы. Сравнения и логические операции возвращают `0` или `1`, а в условиях ноль означает ложь и любое ненулевое значение — истину.

Поддерживаются узлы `const`, `string`, `array`, `elem`, `set`, `length`, `var`, `binop`, `read`, `write`, `assn`, `seq`, `if`, `while`, `do`, `skip`, `sexp` и `switch`. AST-интерпретатор также поддерживает `scope`, `call`, `return` и прежние `decl`, `block`, `callStmt`. `+` складывает числа и объединяет строки или массивы; сравнения строк и массивов лексикографические. Конструкции исходного языка `for`, `elif` и составные присваивания разворачиваются «мордочкой» в эти базовые узлы AST.

## Объявления, функции и dynamic scope

Канонический формат — JSON AST, который выдаёт [референсный веб-интерфейс](https://dboulytchev.github.io/eval.html). Его экспорты используются в файловых тестах. Текстовый парсер в Kotlin-проект не входит.

Область видимости представлена узлом `scope` с массивом объявлений `decls` и исполняемым `body`:

```json
{"scope":{
  "decls":[
    {"name":"x","spec":"var"},
    {"name":"f","spec":{"fun":{"args":[],"body":{"return":{"expr":{"var":"x"}}}}}},
    {"name":"g","spec":{"fun":{"args":["x"],"body":{"return":{"expr":{"call":{"fun":"f","args":[]}}}}}}}
  ],
  "body":{"seq":{
    "left":{"assn":{"dst":"x","src":{"const":1}}},
    "right":{"seq":{
      "left":{"write":{"call":{"fun":"g","args":[{"const":42}]}}},
      "right":{"write":{"var":"x"}}
    }}
  }}
}}
```

Вывод: `42`, затем `1`: `f` читает параметр активного вызова `g`.

| Конструкция | Форма JSON |
| --- | --- |
| Объявление переменной внутри `decls` | `{"name":"x","spec":"var"}` |
| Инициализация или присваивание | `{"assn":{"dst":"x","src":{"const":1}}}` |
| Объявление функции внутри `decls` | `{"name":"f","spec":{"fun":{"args":["n"],"body":{"return":{"expr":{"var":"n"}}}}}}` |
| Вызов | `{"call":{"fun":"f","args":[{"const":3}]}}` |
| Возврат значения | `{"return":{"expr":{"const":3}}}` |
| Возврат без значения | `{"return":""}` |

Все объявления scope регистрируются до выполнения `body`. Переменная создаётся в текущем кадре со значением `0`; её явная инициализация в экспорте записана отдельным `assn`. Порядок таких присваиваний сохраняется из JSON. Повторное объявление переменной или функции в одном кадре — ошибка по условиям задания. Вложенный scope позволяет затенять внешние имена.

`assn` и `read` меняют ближайшую уже объявленную переменную в активной цепочке кадров. Чтение и присваивание необъявленной переменной — ошибки. Переменные и функции используют отдельные пространства имён; встроенную `write` переопределять нельзя.

Объявление функции регистрирует тело без выполнения. Функция ищет переменные и другие функции в активной цепочке вызова, без захвата окружения объявления. Число аргументов проверяется до их вычисления; аргументы вычисляются слева направо в вызывающем кадре, после чего создаётся кадр функции и объявляются параметры. Массивы, строки и S-выражения передаются без глубокого копирования. Поддерживаются рекурсия и вложенные функции.

Референс использует один узел `call` в обоих контекстах. Внутри выражения его значение используется, а при вызове оператором — отбрасывается. `return` немедленно завершает ближайший вызов, включая выход из циклов и scopes; вне функции он запрещён. Возврат без значения и завершение тела без `return` дают `0`, как в референсе.

`seq` не создаёт scope. `scope` создаёт временный кадр; выбранная ветка `switch` также получает кадр для привязок шаблона. Кадры удаляются при завершении, `return` и исключениях.

Для совместимости принимается прежний формат: `decl` с `name/value` или `name/params/body`, `block` со списком операторов, `call` с `name/args`, явный `callStmt`, `return` с выражением напрямую или `null`. Новые файловые программы используют формат веб-интерфейса.

Компилятор сохраняет поддержку старых AST и внешнего `scope`, содержащего только объявления переменных: они преобразуются в существующие инструкции `ST`. Вложенные scopes с объявлениями, пользовательские функции и `return` при компиляции явно отклоняются. Стековая машина не изменена и пользовательские функции не реализует.

Сборка и тесты:

```shell
./gradlew clean test build
```

Запуск тестового AST:

```shell
./gradlew :app:run --args='test.json'
```

Пример суммы всех чисел в массиве произвольной вложенности находится в [`examples/nested_array_sum.json`](examples/nested_array_sum.json). Каждый элемент в нём представлен парой `[флаг, значение]`: `0` обозначает число, `1` — вложенный массив. Запуск примера выводит `15`:

```shell
./gradlew :app:run --args='examples/nested_array_sum.json'
```

## Тестовые программы

Каждый сквозной тест состоит из двух файлов с одинаковым именем:

- [`app/src/test/resources/programs`](app/src/test/resources/programs) содержит исходный код языка в файлах `.in`;
- [`app/src/test/resources/json`](app/src/test/resources/json) содержит соответствующий AST в файлах `.json`.

Входные данные и ожидаемый вывод записаны отдельными переменными `input` и `expectedOutput` непосредственно в [`InterpreterProgramTest.kt`](app/src/test/kotlin/InterpreterProgramTest.kt). Если одну программу нужно проверить на нескольких входах, для неё создаются несколько одинаково оформленных тестовых методов, использующих общую пару `.in`/`.json`.

Тестовый раннер проверяет наличие исходника, разбирает JSON настоящим `GetJsonToAST`, выполняет AST через `ExecutionVisitor`, сравнивает весь вывод и убеждается, что программа использовала все переданные входные значения.

Файловые программы для новых возможностей (каждому имени соответствуют `.in` в `programs` и `.json` в `json`):

| Имя | Проверка | Вход → вывод |
| --- | --- | --- |
| `functions_dynamic_scope` | Функция читает и меняет переменную активного вызывающего кадра | без входа → 41, 1 |
| `functions_recursive_factorial` | Рекурсия и независимые параметры | 6 → 720; 0 → 1 |
| `functions_argument_order` | Аргументы вычисляются слева направо до связывания параметров | без входа → 25, 12 |
| `variable_block_scope` | Затенение в блоке и присваивание ближайшей переменной | без входа → 3, 1, 8 |
| `functions_statement_return` | Вызов оператором, void и ранний выход из цикла/блока | без входа → 45, 8, 1 |
| `functions_switch_scope` | Привязка шаблона видна вызываемой функции и удаляется после ветки switch | без входа → 42, 1 |
| `variable_duplicate_declaration` | Повторное объявление | ожидаемая ошибка |
| `variable_undeclared_assignment` | Присваивание без объявления | ожидаемая ошибка |
| `variable_undeclared_read` | Ввод в необъявленную переменную | ожидаемая ошибка |
| `variable_block_escape` | Доступ к локальному имени после выхода из блока | ожидаемая ошибка |
| `functions_void_expression` | Возврат без значения внутри выражения | без входа → 0 |

Все эти программы подключены к `InterpreterProgramTest` (12 проверок, включая два входа факториала). Четыре негативных сценария проверяют тип и диагностическое сообщение ошибки, а также отсутствие неожиданного вывода. Их можно запустить отдельно:

```shell
./gradlew :app:test --tests '*InterpreterProgramTest.file*'
```

Выполнить отдельный положительный JSON AST:

```shell
./gradlew :app:run --args='app/src/test/resources/json/functions_dynamic_scope.json'
```

Файлы `.in` проверены самим JavaScript референсного веб-интерфейса, а соответствующие JSON получены его экспортом. Реальный парсер отличается от опубликованного описания: тела управляющих конструкций и части заголовка `for` оформлены блоками, после объявления `fun` нет `;`, а возврат без значения записывается `return;`. Отдельные runtime-расхождения с веб-интерпретатором намеренные: повторные объявления запрещены по заданию, `return` корректно выходит из циклов, а ранее реализованные операции строк и массивов сохранены.
