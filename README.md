# Интерпретатор AST

Программа принимает путь к JSON-файлу с AST и выполняет его. Значениями языка могут быть 32-битные целые числа, строки и изменяемые массивы. Сравнения и логические операции возвращают `0` или `1`, а в условиях ноль означает ложь и любое ненулевое значение — истину.

Поддерживаются узлы `const`, `string`, `array`, `elem`, `set`, `length`, `var`, `binop`, `read`, `write`, `assn`, `seq`, `if`, `while`, `do`, `skip`, `sexp` и `switch`. AST-интерпретатор также поддерживает `decl`, `block`, `call`, `callStmt` и `return`. `+` складывает числа и объединяет строки или массивы; сравнения строк и массивов лексикографические. Конструкции исходного языка `for`, `elif` и составные присваивания разворачиваются «мордочкой» в эти базовые узлы AST.

## Объявления, функции и dynamic scope

`decl` создаёт переменную в текущем кадре. Повторное объявление в этом кадре — ошибка; во вложенном кадре имя можно затенить. `assn` и `read` меняют ближайшую уже объявленную переменную в активной цепочке кадров. Чтение и присваивание необъявленной переменной — ошибки. Старые JSON AST, использующие первое присваивание или `read` как объявление, нужно дополнить явными `decl`.

Канонические формы JSON:

| Узел | Пример |
| --- | --- |
| Объявление переменной с обязательным начальным значением | `{"decl":{"name":"x","value":{"const":1}}}` |
| Объявление функции | `{"decl":{"name":"f","params":["n"],"body":{"return":{"var":"n"}}}}` |
| Блок с новой областью видимости | `{"block":[{"decl":{"name":"x","value":{"const":2}}},{"write":{"var":"x"}}]}` |
| Вызов в выражении | `{"call":{"name":"f","args":[{"const":3}]}}` |
| Вызов как оператор | `{"callStmt":{"name":"f","args":[{"const":3}]}}` |
| Возврат значения / возврат без значения | `{"return":{"const":3}}` / `{"return":null}` |

Объявление функции регистрирует её тело, не выполняя его. Объявления вступают в силу по мере выполнения, без предварительного подъёма. Функция ищет переменные и другие функции в кадре вызова и далее в активных внешних кадрах, без захвата окружения объявления. Переменные и функции используют отдельные пространства имён; повторное объявление функции в одном кадре — ошибка. Встроенную `write` переопределять нельзя.

Число аргументов проверяется до их вычисления. Аргументы вычисляются слева направо в вызывающем кадре; затем создаётся кадр функции и в нём объявляются параметры. Строки, массивы и S-выражения передаются как существующие изменяемые значения, без глубокого копирования. Поддерживаются рекурсия и вложенные объявления функций.

`return` немедленно завершает ближайший вызов, включая выход из циклов и блоков; вне функции он запрещён. Завершение тела без `return` и `return: null` не дают значения. `call` требует возвращённое значение, `callStmt` отбрасывает результат и допускает отсутствие значения. `write` — оператор с одним аргументом, без возвращаемого значения.

`seq` не создаёт scope. `block` создаёт scope на время выполнения списка операторов. Выбранная ветка `switch` также получает временный кадр для привязок шаблона и локальных объявлений. Кадры удаляются при обычном завершении, `return` и исключениях.

Компилятор поддерживает объявления переменных через существующую инструкцию `ST`, чтобы общие тестовые программы выполнялись в обоих режимах. Пользовательские функции, `return` и блоки со scope доступны только в AST-интерпретаторе; при компиляции они явно отклоняются. Стековая машина сохраняет прежнюю семантику инструкций и не реализует пользовательские функции. Парсера исходного языка в проекте нет: файлы `.in` служат примерами, а исполняется JSON AST.

Пример динамической области видимости:

```json
{"block":[
  {"decl":{"name":"x","value":{"const":1}}},
  {"decl":{"name":"f","params":[],"body":{"return":{"var":"x"}}}},
  {"decl":{"name":"g","params":["x"],"body":{"return":{"call":{"name":"f","args":[]}}}}},
  {"write":{"call":{"name":"g","args":[{"const":42}]}}},
  {"write":{"var":"x"}}
]}
```

Вывод: `42`, затем `1`: `f` читает параметр активного вызова `g`.


Сборка и тесты:

```shell
./gradlew clean test build
```

Запуск тестового AST:

```shell
./gradlew :app:run --args='test.json'
```

Пример суммы всех чисел в массиве произвольной вложенности находится в [`examples/nested_array_sum.json`](examples/nested_array_sum.json). Каждый элемент в нём представлен парой `[флаг, значение]`: `0` обозначает число, `1` — вложенный массив. Запуск примера выводит `15`:

```shell
./gradlew :app:run --args='examples/nested_array_sum.json'
```

## Тестовые программы

Каждый сквозной тест состоит из двух файлов с одинаковым именем:

- [`app/src/test/resources/programs`](app/src/test/resources/programs) содержит исходный код языка в файлах `.in`;
- [`app/src/test/resources/json`](app/src/test/resources/json) содержит соответствующий AST в файлах `.json`.

Входные данные и ожидаемый вывод записаны отдельными переменными `input` и `expectedOutput` непосредственно в [`InterpreterProgramTest.kt`](app/src/test/kotlin/InterpreterProgramTest.kt). Если одну программу нужно проверить на нескольких входах, для неё создаются несколько одинаково оформленных тестовых методов, использующих общую пару `.in`/`.json`.

Тестовый раннер проверяет наличие исходника, разбирает JSON настоящим `GetJsonToAST`, выполняет AST через `ExecutionVisitor`, сравнивает весь вывод и убеждается, что программа использовала все переданные входные значения.

Файловые программы для новых возможностей (каждому имени соответствуют `.in` в `programs` и `.json` в `json`):

| Имя | Проверка | Вход → вывод |
| --- | --- | --- |
| `functions_dynamic_scope` | Функция читает и меняет переменную активного вызывающего кадра | без входа → 41, 1 |
| `functions_recursive_factorial` | Рекурсия и независимые параметры | 6 → 720; 0 → 1 |
| `functions_argument_order` | Аргументы вычисляются слева направо до связывания параметров | без входа → 25, 12 |
| `variable_block_scope` | Затенение в блоке и присваивание ближайшей переменной | без входа → 3, 1, 8 |
| `functions_statement_return` | Вызов оператором, void и ранний выход из цикла/блока | без входа → 45, 8, 1 |
| `functions_switch_scope` | Dynamic scope привязки шаблона и значение switch в выражении | без входа → 42, 1 |
| `variable_duplicate_declaration` | Повторное объявление | ожидаемая ошибка |
| `variable_undeclared_assignment` | Присваивание без объявления | ожидаемая ошибка |
| `variable_undeclared_read` | Ввод в необъявленную переменную | ожидаемая ошибка |
| `variable_block_escape` | Доступ к локальному имени после выхода из блока | ожидаемая ошибка |
| `functions_void_expression` | Void-функция внутри выражения | ожидаемая ошибка |

Все эти программы подключены к `InterpreterProgramTest` (12 проверок, включая два входа факториала). Негативные сценарии проверяют тип и диагностическое сообщение ошибки, а также отсутствие неожиданного вывода. Их можно запустить отдельно:

```shell
./gradlew :app:test --tests '*InterpreterProgramTest.file*'
```

Выполнить отдельный положительный JSON AST:

```shell
./gradlew :app:run --args='app/src/test/resources/json/functions_dynamic_scope.json'
```
